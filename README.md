# World info

World info 是一个可在本机管理、由 GitHub Actions 云端定时运行的全球信息采集与管理工具。当前使用 TrendRadar 6.10.0 采集 44 个精选 RSS/热榜来源，以 SQLite 文件保存数据，并提供浏览器可视化界面管理关注领域、信息源、筛选规则和定时设置。

系统支持 DeepSeek-V4.1-Flash 做价值筛选、跨语言事件合并、分类和中文摘要。首次使用运行 `设置DeepSeek.cmd`；密钥只保存在本机 `.env` 和 GitHub Actions Secret，不会写进仓库。未配置时仍可生成无 AI 原文速览。

无 AI 速览使用可配置的软配额：默认政治与经济热点 4 条、科技与电子信息 4 条、生物科学与脑科学 2 条。某组内容不足时不会凑数，空位会按原候选顺序分配给其他组。

## 现在怎么使用

项目位于：

```text
D:\Fun Project\World info
```

最简单的方法是双击：

```text
打开面板.cmd
```

也可以在 PowerShell 执行：

```powershell
.\open-dashboard.ps1
```

它会在本机启动界面并打开：

```text
http://127.0.0.1:8765
```

界面只监听 `127.0.0.1`，同一局域网的其他设备不能访问。

## 可视化界面

- **今日简报**：查看最近采集、来源状态和真实简报预览；“立即生成预览”会运行当前筛选流程，但不会发送飞书，也不会写入已读状态。
- **内容设置**：直接调整每日条数、4/4/2 分类配额、筛选强度和摘要长度。观察窗口、去重周期、关注领域等低频参数收在“高级设置”中。
- **信息源**：启用、停用、修改或增加 RSS；管理来源优先级和新鲜度。
- **定时推送**：调整每天的推送时间、采集间隔、DeepSeek 开关和接收渠道。
- **系统状态**：查看项目路径、后台心跳以及密钥是否配置，只显示状态，不显示密钥。

右侧“手机预览”读取最近一次真实简报结果，只显示文字、摘要和来源。保存设置后，新的条数、配额、筛选阈值和摘要长度会用于下一次预览与正式推送。

点击“保存设置”后，界面会先调用程序的完整配置校验。校验失败不会覆盖当前有效配置。用户修改保存在：

```text
config\user-settings.yaml
config\user-sources.yaml
```

每次保存前的旧版本放在 `config\backups\`。基础模板 `settings.yaml` 和 `sources.yaml` 保持不变。

## 运行方式

只打开设置界面：

```powershell
.\run.ps1 dashboard
```

只采集一次：

```powershell
.\run.ps1 collect
```

持续采集并同时提供可视化界面：

```powershell
.\run.ps1 serve
```

开机登录后自动运行：

```powershell
.\install-task.ps1
```

查看状态和运行测试：

```powershell
.\run.ps1 status
.\run.ps1 test
```

`serve` 每分钟读取一次配置，并按 `schedule.collect_minutes` 决定是否采集。开启 DeepSeek 后，到简报时间会先筛选、合并和摘要，再发送到飞书。

GitHub Actions 使用 UTC cron 表达北京时间计划：20:43 主任务启动后等待到 22:00，再在 22:11、22:41 和 23:11 自动补偿重试；每日状态和并发锁会阻止正常情况下的重复发送。23:30 以后到达的晚点任务会跳过，避免凌晨打扰。若前一晚仍未成功，系统会在次日 07:17 启动恢复任务，重新采集当时的最新内容，并只补发一次。最后一次重试或晨间恢复若 AI 服务失败，会自动改发无 AI 原文速览；若正常简报和降级简报都失败，则尝试向飞书发送故障提醒。

GitHub 官方没有为定时任务提供准时率 SLA，平台高负载时仍可能延迟甚至丢弃事件。当前多次触发显著降低了普通排队延迟导致的漏发风险；如果要求在 GitHub 整个平台故障时也能补发，后续应增加一个独立于 GitHub 的外部监控和触发器。

## 今天在手机收到飞书推送

1. 在飞书创建一个包含自己的群，进入群设置 → 群机器人 → 添加自定义机器人，复制其 Webhook。若设置安全关键词，填 `全球高质量信息简报`；先不要启用 IP 白名单或签名校验。
2. 双击 `设置飞书Webhook.cmd`，在本机窗口粘贴地址；输入不会显示。脚本会自动开启无 AI 飞书推送、重新采集并发送今天的简报。不要把 Webhook 发在聊天中。
3. 在手机飞书群中核对标题和链接。以后想手动再发，可双击 `立即推送.cmd`。

仅打开设置面板不会自动定时采集/推送。想让电脑开机后常驻运行，可按下文安装登录任务；想让电脑关机时仍推送，见 [GitHub 云端方案](docs/GitHub云端推送.md)。

云端方案已提供一键部署入口：保证电脑能访问 GitHub 后，双击“部署到GitHub.cmd”，按浏览器提示登录 GitHub。脚本会创建私有仓库、把飞书 Webhook 保存为 Actions Secret，并发送一条云端连接测试；不会把 .env 或完整本地简报上传。

## 当前数据流

```text
机构 / 专业媒体 / 工程社区 RSS + 少量财经与社会热榜
    ↓ TrendRadar 采集器
本地 SQLite（按日期保存）
    ↓ 时效、来源和硬去重规则
本地可视化界面：查看状态、编辑设置、手动采集
```

原始数据位于 `output\raw\rss\` 和 `output\raw\news\`。`output\collection.json` 是最近一次来源状态。界面展示的“近期采集”只表示标题进入候选窗口，不代表内容经过 AI 判断或事实核查。

## 接入 DeepSeek

1. 登录 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys)，创建 API Key，并确保账户有可用余额。
2. 双击项目根目录的 `设置DeepSeek.cmd`，在本机窗口粘贴密钥。输入不会显示。
3. 脚本会测试 `deepseek-flash`、开启本机 AI、写入 GitHub Actions Secret、更新私有仓库并运行云端校验。
4. 若想立即看效果，校验成功后双击 `立即推送.cmd`；否则等待每天 22:00 自动推送。

当前模型通过 OpenAI-compatible Chat Completions 接入，并启用 JSON 输出和非思考模式。程序同时保留：

- OpenAI-compatible API 切换；
- AI 来源 ID 校验和链接回填；
- 默认只接受最近 36 小时内有明确发布时间的 RSS 内容，避免把首次采集到的旧文章误当成当天新闻；
- AI 先从按 4/4/2 比例平衡的候选中返回最多 20 条短名单，再由程序按政治经济 4 条、科技 4 条、生物科学 2 条收口；合格内容不足时才把空位分给其他类别；
- AI 返回截断、无效 JSON 或重复来源 ID 时，会自动把输入候选从 80 条缩到 40 条重试一次；
- 每份/每日条数硬限制；
- 飞书、Telegram、企业微信和邮件发送；
- 失败恢复与跨日去重。

在未配置密钥时开启相关功能，`ready` 检查会明确报出缺失项，不会静默运行。
